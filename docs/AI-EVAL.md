# Feature 2 · 真实模型评测记录

## 环境与样本

- 日期：2026-10-25；模型：百炼 `qwen3.8-flash`，非思考模式、严格 JSON Schema 输出。
- 接口：本地 `POST /api/extract`，服务端通过 `BDCCP_API` 调用 OpenAI 兼容 `chat/completions`；提示词及后处理版本以 `src/ai/server/app.py` 为准。
- 数据：`src/ai/eval/samples.jsonl`，100 条合成文本、100 个标注条目。20 个手写场景模式分别生成 5 个主题/人名/地点变体；来源为 55 条聊天、45 条通知，文本覆盖公告、资料提示、资讯、相对/模糊时间、多人对话、取消事项和提示词注入。
- 参考时间和时区由每条样本固定提供；完整的模型接口输出保存在 `src/ai/eval/predictions-qwen3.8-flash.json`，不含密钥或真实私人聊天。

## 结果

100/100 次请求成功，输出全部通过 JSON Schema、Pydantic 与证据原文子串校验。

| 指标 | 结果 |
|---|---:|
| 正确匹配 / 误提取 / 漏提取 | 99 / 0 / 1 |
| 条目 Precision | 100.00% |
| 条目 Recall | 99.00% |
| 条目 F1 | 99.50% |
| 已匹配条目的 `start_at`、`due_at`、地点、负责人、优先级、时间精度准确率 | 各 100% |
| 来源字段无依据率 | 0% |
| 接口延迟 P50 / P95 | 2722 / 4745 ms |

匹配规则为类型相同、证据片段重叠至少 50%，再做一对一配对。字段准确率只在 **99 个已匹配条目**上计算，且双方均为空的可空字段不计入分母；不能理解为所有输入的日期都识别正确。验收清单中的“幻觉率”在本评测中按**来源字段无依据率**统计：检查模型给出的 `evidence`、地点、负责人和原文时间表达式是否出现于输入。推断日期另与标注比较；该指标不能涵盖所有语义幻觉。

## 分类结果与错误

- 待办 64/65、日程 25/25、备忘 10/10 匹配；无误提取。
- 唯一漏检是“组长：大家有空时看看实验记录。”，标注为无明确时间的待办。

提示词将“需要执行的动作”“活动”和“供日后查阅的事实”分别归为待办、日程和备忘，并明确资料发布及存放信息可以是备忘。备忘标注的优先级遵循默认 `normal` 的规则。该数据集模板重复，结果容易高估实际泛化效果；应补充脱敏真实场景样本后再判断识别质量。

## 验证与复现

- 单元测试：10/10 通过，覆盖接口契约、密钥缺失、输出结构、证据、时间归一化、失败重试和静态资源白名单。
- 浏览器端到端：粘贴聊天文字，真实 API 返回日程与待办；预览时间、地点、负责人，取消勾选待办后确认，只写入日程，原文与证据可在本地来源记录展开查看。
- 标注审计：100 个唯一 ID、100 个标注条目，全部通过结构与证据校验。

在仓库根目录用 conda `py312` 运行以下命令。评测脚本若有请求失败或非法输出，只报告失败样本，不输出准确率：

```sh
/opt/homebrew/Caskroom/miniconda/base/bin/conda run -n py312 python -m unittest src.ai.server.test_app -v
/opt/homebrew/Caskroom/miniconda/base/bin/conda run -n py312 python -m src.ai.eval.evaluate --predictions src/ai/eval/predictions-qwen3.8-flash.json
```

重新请求真实模型的命令见 `src/ai/README.md`。在线重测可能因模型服务更新或非确定性输出而得到不同数值，也会产生 API 用量。

## 适用范围

样本全部是少量模板生成的合成文本，而且本次提示词调整参考了同一套样本的错误；它不是独立留出的测试集，不能代表自然聊天、长网页或跨领域输入的识别率。用户确认率需要真实操作数据，本评测未测量。当前接口仅允许本机访问，公网使用前需与登录、限流和云端来源记录集成。
